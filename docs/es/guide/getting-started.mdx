## Crear un Store

Cualquier custom Hook puede convertirse en estado compartido al envolverlo con `createStore`.

```tsx
import { createStore } from '@violetflux/kerros'
import { useState } from 'react'

interface Task {
  id: string
  title: string
}

function useTaskModel() {
  const [tasks, setTasks] = useState<Task[]>([])

  const addTask = (task: Task) => {
    setTasks(v => [...v, task])
  }

  const finishTask = (taskId: string) => {
    setTasks(v => v.filter(task => task.id !== taskId))
  }

  return { tasks, addTask, finishTask }
}

export const [useTask, TaskProvider, getTask] = createStore(useTaskModel)
```

`createStore` devuelve el Hook que usan los componentes, su Provider y un getter imperativo para las instancias confirmadas fuera de React. Dentro del Store puedes seguir usando `useState`, `useReducer`, Context, Hooks de SDK o tus propios Hooks.

Mantén el initializer como un Hook con nombre en el nivel superior, por ejemplo `useTaskModel`. Los initializers anónimos siguen funcionando, pero React Compiler no los compila automáticamente como Hooks en modo `infer`.

## Montar el Provider

`useTask` solo puede llamarse dentro de los descendientes de `TaskProvider`.

```tsx
function App() {
  return (
    <TaskProvider>
      <Header />
      <TaskList />
    </TaskProvider>
  )
}
```

Fuera del Provider, Kerros lanza un error claro.

## Usar el Store en un componente

Llama a `useTask()` sin argumentos y desestructura inmediatamente los campos necesarios. El seguimiento automático es el modo predeterminado.

```tsx
function TaskList() {
  const { tasks, finishTask } = useTask()

  return (
    <ul>
      {tasks.map(task => (
        <li key={task.id}>
          {task.title}
          <button onClick={() => finishTask(task.id)}>Terminar</button>
        </li>
      ))}
    </ul>
  )
}
```

Kerros sigue los campos leídos durante el renderizado. Los cambios en campos no leídos no vuelven a renderizar `TaskList`. Usa selectores explícitos solo para valores derivados o puntos críticos medidos.

## Varias instancias

Cada Provider montado crea un Store independiente.

```tsx
<TaskProvider>
  <h2>Tareas personales</h2>
  <TaskList />
</TaskProvider>

<TaskProvider>
  <h2>Tareas del equipo</h2>
  <TaskList />
</TaskProvider>
```

Cada `TaskList` lee automáticamente el Provider más cercano. Los datos permanecen aislados.

## Dependencias entre Stores

Un Store puede llamar directamente a otro Store.

```tsx
function useTaskModel() {
  const { user } = useAccount()
  const [tasks, setTasks] = useState<Task[]>([])

  const addTask = (title: string) => {
    if (!user)
      return

    setTasks(v => [...v, {
      id: crypto.randomUUID(),
      title,
      assigneeId: user.id,
    }])
  }

  return { tasks, addTask }
}

export const [useTask, TaskProvider] = createStore(useTaskModel)
```

Monta el Provider de la dependencia por fuera y mantén la dependencia en una sola dirección.

```tsx
<AccountProvider>
  <TaskProvider>
    <App />
  </TaskProvider>
</AccountProvider>
```

## Pasar props al Provider

Las props del Provider se pasan al Hook del Store.

```tsx
function useCounterModel({ initialCount }: { initialCount: number }) {
  const [count, setCount] = useState(initialCount)
  return { count, setCount }
}

const [useCounter, CounterProvider] = createStore(useCounterModel)
```

```tsx
<CounterProvider initialCount={42}>
  <Counter />
</CounterProvider>
```
